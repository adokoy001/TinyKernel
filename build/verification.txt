SECURITY BOUNDARIES AND CURRENT LIMITS
Each User process has its own CR3, RX code, RW/NX data and 8 KiB RW/NX stack
with unmapped guards. Four page-table frames, four user-memory frames and a
16 KiB kernel stack total 12 frames, all charged to User even for an Admin
caller. The User frame limit is 24, so at most two such processes fit when
no other User frames are allocated. Processes never reuse PIDs within a boot.
Syscall input is copied only after validating the complete user range; output
writes are similarly checked before storage effects or handle cursor changes.
TSS IO bitmap is beyond its architectural 104-byte limit, denying User I/O.
SYSCALL/SYSENTER alternate entries, FSGSBASE and OSXSAVE are disabled;
FS/GS bases are zero. CR0.TS/MP traps unsupported x87/MMX/SSE state. No FPU,
SIMD, TLS, dynamic linking, heap, fork, POSIX compatibility or network syscalls.
Executable files use a strict original 32-byte Tane header, <=4096-byte total,
with one code page and one data/BSS page; no ELF loader or relocations.
The Shell and trusted demonstration tasks remain ring 0. File MAC is shared
Admin/User domain policy, not PID-specific private files or per-user ACLs.
Four handles per process have immutable rights, owning PID, non-reused tokens
and mutation identities checked on each read/write. Exit, kill and fault
revoke handles; after leaving the task stack/CR3, all 12 frames are wiped and
returned to the immutable charge owner. Bounded exit/output records remain.
Stdout retains 1024 bytes per process lifetime, with eight recent outcomes;
reading output does not drain the limit. Control bytes are escaped on display.

Storage operations serialize against user syscalls. Stage/apply masks interrupts
across the entire validation/snapshot/revision/consume/effect/discard transaction,
closing the plan check/use race introduced by concurrent user file mutations.
The deterministic guest plan test covers changed revisions; the narrow race
itself is closed by inspection of the uninterrupted critical section, not a
forced race schedule.
Plans are not a journal or power-failure rollback. In-memory failing disk tests
cover error handling; physical disk errors, stack-canary overflow and real
hardware/UEFI were not reproduced. Network remains static ARP/NDP/ICMP without
TCP/UDP/DNS. Hardware fault probes and QEMU tests are evidence of these specific
boundaries, not a claim of complete security for arbitrary hardware or programs.
